# 筛选交互检查（filter-check）

## 何时触发

- 给列表/清单类页面**新增或修改**了筛选功能之后，提交前必查
- 用户反馈"筛选后列表不对""筛不回去了"这类问题时

## 检查步骤

逐条执行。每条都要有**能亲眼确认的证据**（页面实际显示、命令输出），不接受"应该没问题"。

### 1. 有结果

- **操作**：点选一个能命中至少一项的筛选条件（如「已完成」，且当前确有已完成项）
- **检查**：列表只显示符合条件的项，不符合的不出现；显示的条数和实际符合的条数一致

### 2. 无结果

- **操作**：点选一个命中零项的筛选条件（如「已完成」，但当前没有任何完成项）
- **检查**：出现**专门的空态提示**（文案说明"没有符合条件的项"）——不是白屏、不是残留上一次的列表、也不是报错

### 3. 清空恢复

- **操作**：点「全部」（或清空筛选条件）
- **检查**：列表恢复为筛选前的完整内容，逐项与筛选前一致；筛选状态本身也复位——按钮高亮回到「全部」，不能还停在刚才的条件上

## 输出格式

检查完按下表报告，三条都要填，缺一不算检查完：

| 检查项 | 结果 | 证据 |
| --- | --- | --- |
| 有结果 | ✅ / ❌ | （页面显示 / 截图说明） |
| 无结果 | ✅ / ❌ | （同上） |
| 清空恢复 | ✅ / ❌ | （同上） |

**任何一条 ❌ 即整体不通过**。修复后三条全部重测——因为改动很可能影响另外两条，不许只补测失败的那条。
